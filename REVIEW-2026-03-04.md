## ТОП-20 критичных проблем (кросс-функциональный приоритет)

### Безопасность сервера (НЕМЕДЛЕННО)

1. **🔴 Пароль root в документации репозитория** — `deployment.md` содержит `sshpass -p 'Vibecoder'`. Сменить пароль, удалить из истории git, перейти на SSH-ключи *(DevOps)*
2. **🔴 `PermitRootLogin yes` + Password Auth по SSH** — открыт brute-force вектор *(DevOps)*
3. **🔴 TLS 1.0/1.1 включены** в `nginx.conf` — нарушение PCI DSS *(DevOps)*
4. **🔴 Нет резервных копий PostgreSQL** — полная потеря данных при сбое диска *(DevOps, БД)*

### Безопасность приложения

5. **🔴 JWT передаётся в URL** (SSE stream + editor preview) — токен в логах Nginx, Referer, истории браузера *(Frontend, Backend, QA)*
6. **🔴 CORS в forms.ts отражает любой Origin** — CSRF-атака на формы пользователей *(Backend, QA)*
7. **🔴 Race condition при деплое** — два одновременных деплоя ломают версии и файлы *(Backend, QA, БД)*
8. **🔴 Rate limiter без Redis** — сбрасывается при рестарте PM2 *(Backend, DevOps, QA)*
9. **🔴 `npm run build` без sandbox** — произвольное выполнение кода из `package.json` пользователя *(Backend, QA, DevOps)*
10. **🔴 SVG upload = stored XSS** — `image/svg+xml` разрешён, но SVG не санируется *(Backend)*

### Бизнес-логика

11. **🔴 Webhook-идемпотентность не гарантирована** — Prodamus может начислить AI-кредиты дважды *(QA, Backend)*
12. **🔴 Тариф BUSINESS на лендинге, но не реализован** в бэкенде — обман ожиданий *(Маркетинг)*
13. **🔴 Расхождение условий PRO** между Pricing (1 ГБ) и Офертой (200 МБ) *(Маркетинг)*
14. **🔴 Нет транзакций** в deploy/billing/gallery — неконсистентное состояние БД при сбоях *(БД)*

### Аналитика и маркетинг

15. **🔴 Яндекс.Метрика не установлена на сам hostingvibe.ru** — нет данных о воронке *(Аналитика, Маркетинг)*
16. **🔴 `vibe-analytics.js` не инжектируется** при деплое — дашборд аналитики пустой у всех пользователей *(Аналитика)*
17. **🔴 Нет OG-изображения и favicon** — пустая карточка при шаринге *(Маркетинг)*
18. **🔴 Нет robots.txt** — dashboard/admin индексируются поисковиками *(Маркетинг)*

### UX и доступность

19. **🔴 VibeEditor ломается на мобильном** — `w-80` боковая панель не адаптирована *(Дизайн)*
20. **🔴 Нет `prefers-reduced-motion`** — нарушение WCAG 2.1 *(Дизайн)*

# 1. Frontend-разработчик

## 1.1 Безопасность

### 🔴 КРИТИЧНО: JWT-токен в URL при SSE-стриминге
**Файл:** `frontend/src/lib/api.ts:168`

```typescript
const url = `${API_URL}/projects/${projectId}/deployments/${deploymentId}/stream${token ? `?token=${encodeURIComponent(token)}` : ''}`;
```

JWT передаётся в query-параметре URL. Это значит, что он логируется в Nginx access.log, попадает в Referer при переходах, виден в истории браузера.

**Решение:** Использовать кастомный EventSource через `fetch()` со `ReadableStream`, либо проксировать через Next.js API route с передачей токена в cookie.

### 🔴 КРИТИЧНО: Токен редактора в URL превью
**Файл:** `frontend/src/lib/api.ts:347-357`

JWT в URL iframe-а. Логируется на бекенде.

### 🟡 JWT только в localStorage без httpOnly cookie
**Файл:** `frontend/src/lib/api.ts:17-25`

Cookie не имеет флага `HttpOnly` — доступна из JS. При XSS-атаке злоумышленник получит токен.

### 🟡 Хардкод IP сервера в клиентском коде
**Файл:** `frontend/src/app/(dashboard)/domains/page.tsx:19`

```typescript
const SERVER_IP = '213.159.209.228';
```

При смене IP потребуется пересборка фронтенда. Лучше отдавать с бекенда.

### 🟡 `document.execCommand('copy')` — устаревший API
**Файл:** `frontend/src/app/ai/AiPageContent.tsx:63-70`

# 2. Backend-разработчик

## 2.1 Безопасность

### 🔴 КРИТИЧНО: Нет лимита на размер тела JSON-запроса
**Файл:** `backend/src/index.ts:48`

```typescript
app.use(express.json());  // лимит по умолчанию — 100 KB
```

Для `/api/forms/:slug` нет ограничения числа полей. Атакующий может создать форму с тысячами полей.

**Решение:** `app.use(express.json({ limit: '100kb' }));`

### 🔴 КРИТИЧНО: CORS — wildcard отражение Origin без whitelist
**Файл:** `backend/src/routes/forms.ts:10-22`

```typescript
res.setHeader('Access-Control-Allow-Origin', origin);  // любой origin!
```

**Решение:** Проверять, что origin принадлежит `*.hostingvibe.ru` или зарегистрированному домену проекта.

### 🔴 КРИТИЧНО: Race condition при деплое — нет конкурентной блокировки
**Файл:** `backend/src/routes/deploy.ts:83`

Два деплоя одновременно прочитают одинаковый `currentVersion`, оба попытаются `fs.renameSync(siteDir)`.

**Решение:** Добавить `Map<projectId, Promise>` как in-process мьютекс, или использовать BullMQ (уже в `package.json`).

### 🟡 `npm run build` без sandbox
**Файл:** `backend/src/services/deploy.service.ts:88`

Lifecycle hooks удалены, но `build` script — произвольный shell-код из пользовательского `package.json`.

### 🟡 Открытый редирект в forms.ts
**Файл:** `backend/src/routes/forms.ts:94-101`

Относительный путь позволяет фишинг через `/_vibe_redirect=/billing?...`.

### 🟡 SVG upload → stored XSS
**Файл:** `backend/src/routes/edit.ts:29-40`

`image/svg+xml` разрешён. SVG может содержать `<script>`. Файл отдаётся напрямую Nginx.

### 🟡 Слабая проверка имени файла при выгрузке ассетов
**Файл:** `backend/src/routes/edit.ts:20-23`

Пользователь может прислать файл с именем `image.jpg` и mime `image/svg+xml`. Multer не проверяет magic bytes.

### 🟡 JWT-токен в URL query-параметре
**Файл:** `backend/src/middleware/auth.ts:31-33`

JWT в URL логируется в access-логах Nginx, попадает в Referer.

**Решение:** Short-lived one-time token через Redis.

### 🟢 CSP отключён на уровне Helmet
**Файл:** `backend/src/index.ts:33-36`

API-сервер сам отдаёт HTML в `site-gate.ts` и preview — CSP для них не установлен.

## 2.2 Аутентификация и авторизация

### 🟡 adminMiddleware — лишний DB-запрос при каждом admin-запросе
**Файл:** `backend/src/middleware/auth.ts:49-59`

Можно добавить `isAdmin` в JWT-payload.

### 🟡 Нет механизма отзыва токенов / logout
JWT с TTL 30 дней, но нет `POST /api/auth/logout`. При краже токена нет способа инвалидировать.

**Файл:** `backend/src/middleware/auth.ts:40`

Блокирует всю Node.js event loop на время сборки (до 3 минут).

# 8. Архитектор БД

## 8.1 Схема данных

### 🟢 Хорошо: CUID для PK, BigInt для sizeBytes, snake_case в БД через @map(), enums вместо строк.

### 🔴 `TelegramLink.chatId` не уникален
Позволяет привязать один Telegram-чат к нескольким пользователям.

```prisma
chatId  String  @unique @map("chat_id")
```

### 🟡 `VisualPatch.type` — String вместо enum
Допустимо только 4 значения, но ограничение только на уровне приложения.

### 🟡 `EditorPage.gjsData` — JSONB без лимита размера
GrapesJS-состояние может достигать сотен KB.

## 8.2 Индексы

### 🟢 Хорошо: составные индексы для галереи, PageView, ProjectLike.

### 🟡 Избыточные индексы
`@@index([email])` на users — дублирует `@unique`. Аналогично `@@index([token])` на PasswordReset.

### 🟡 Нет индекса `(projectId, version)` на Deployment
Rollback делает sequential scan.

### 🟡 Нет индекса `(projectId, enabled)` на VisualPatch
Публичный endpoint `/api/patches/:slug` всегда `WHERE enabled = true`.

## 8.3 Целостность данных

### 🔴 Нет транзакций в критических операциях

**Deploy (deploy.service.ts:302–339):** 4 отдельных UPDATE без транзакции. При сбое между ними — неконсистентное состояние.

**Billing webhook (billing.ts:217–232):** Активация подписки и смена плана — два отдельных UPDATE.

**Gallery (gallery.ts:204–211):** Лайк/анлайк — create/delete + increment/decrement без транзакции.

**Delete (projects.ts:262–270):** Удаление проекта и пересчёт storageUsed — отдельные запросы.

### 🟡 Денормализация счётчиков — риск рассинхронизации
`Project.views` и `Project.likes` хранятся и в денормализованном виде, и в отдельных таблицах.

## 8.4 Паттерны запросов

### 🟡 storageUsed пересчитывается через полное сканирование
В 4 местах — `findMany` + `reduce` в JavaScript. Лучше: `prisma.project.aggregate({ _sum: { sizeBytes: true } })`.

### 🟡 SSE-поллинг БД каждые 1.5 секунды
**Файл:** `backend/src/routes/deploy.ts`

При 10 деплоях — 400+ запросов/мин. Лучше: Redis pub/sub или PostgreSQL LISTEN/NOTIFY.

## 8.5 Redis

### 🔴 Redis настроен, но фактически не используется для rate limiting
**Файл:** `backend/src/middleware/rateLimit.ts`

`rate-limit-redis` установлен, но `express-rate-limit` использует in-memory store.

### 🟡 Три in-memory Map вместо Redis
- `analytics.service.ts`: `recentViews`
- `gallery.ts`: `recentViews` (дублирует!)
- `gallery.ts`: `guestLikes`

При перезапуске все данные теряются. Redis SETEX решает проблему.

## 8.6 Миграции

### 🟢 Хорошо: миграции атомарны, нет деструктивных DROP.
### 🟡 Нет автозапуска `prisma migrate deploy` при деплое
### 🟡 Нет rollback-стратегии

## 8.7 Soft Delete

### 🟡 Не реализован нигде
При удалении проекта данные каскадно уничтожаются. Нет возможности восстановить.

## 8.8 Аудит

### 🟡 Нет audit-лога
Смена плана, платежи, suspend проекта — не фиксируются в отдельной таблице.

Рекомендуется:
```prisma
model AuditLog {
  id        String   @id @default(cuid())
  userId    String?
  action    String   // "plan_upgraded", "project_suspended"
  entityId  String?
  metadata  Json?
  createdAt DateTime @default(now())
  @@index([userId, createdAt])
  @@index([action, createdAt])
}
```

## 8.9 Безопасность данных

### 🟢 IP хешируются SHA-256, пароли через bcrypt(10), PasswordReset.token — SHA-256.
### 🟡 `Domain.verifyToken` не очищается после верификации
### 🟡 `FormSubmission.data` — нет TTL очистки (GDPR/152-ФЗ)

## 8.10 Пул соединений

### 🟡 PrismaClient без явного `connection_limit`
По умолчанию `num_cpus * 2 + 1` (~5). При пиковой нагрузке может не хватить.

## 8.11 Масштабируемость page_views

### 🟡 Нет стратегии архивации
При 100 сайтах × 1000 просмотров/день = 3 млн строк/месяц. `COUNT(*)` будет замедляться.

Решения:

2. Партиционирование по месяцам
